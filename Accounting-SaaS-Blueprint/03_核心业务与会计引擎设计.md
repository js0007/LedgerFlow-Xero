## 1. 第一性原理与核心会计不变量（Accounting Invariants）

1. **复式平衡不变量（Double-Entry Conservation）：** 每一个已过账 `Journal` 的全部分录行必须满足：
   $$\sum_{i \in \text{lines}} \text{debit}_i = \sum_{i \in \text{lines}} \text{credit}_i \quad (\text{精确至 } 0.0001 \text{ 内部精度，对外本位币 } 0.01)$$
2. **总账只增不改不变量（Append-Only Immutability）：** `journals` 与 `journal_lines` 表一旦写入即永久锁定（PostgreSQL 触发器禁止 `UPDATE` 与 `DELETE`）。任何撤回、作废、重分类或自动冲销**只能通过插入逆向冲销分录（`reversal_of_journal_id`）实现**。
3. **受控科目子账唯一入口不变量（Subledger-to-GL Integrity）：**
   - `610 Accounts Receivable (SYSTEM: DEBTORS)` 只能由 Sales Invoice / Sales Credit Note / Sales Payment / Conversion Balance 过账驱动。
   - `800 Accounts Payable (SYSTEM: CREDITORS)` 只能由 Purchase Bill / Supplier Credit Note / Purchase Payment / Conversion Balance 过账驱动。
   - `BANK` 类型科目只能由 BankTransaction (Spend/Receive/Transfer) / Payment 驱动。
   - `ManualJournal` 服务层依据 [au-seed-data.json](file:///d:/ai-work/au-faiw/xero%E8%B0%83%E7%A0%94/Accounting-SaaS-Blueprint/schemas/au-seed-data.json) 的 `manualJournalExcluded` 规则**硬拒绝**直接借贷 **7 个非银行排除科目**（`497`, `498`, `610`, `630`, `800`, `801`, `877`）及全部 `BANK` 账户（其余 47 个含 `804/820/825/826/840/850/860/960` 均可在 Manual Journal 中用于调整/冲销，已由 `E29-NET` 实证）。
4. **单调凭证号与租户顺序锁：** 每个组织维护独立严格单调递增序列 `journal_number`（`1, 2, 3...`），由 `SELECT ... FOR UPDATE` 或组织序列分配器在事务提交前颁发，保障 BAS 水位线精准捕获每一条变更。

## 2. 税额与舍入计算引擎（Tax & Line-by-Line Rounding）

参照 Xero AU 实测规则 (`[Documented]` + `E21`, `E24`)，所有含行项目的业务单据统一经过纯函数 `calculateLineAmounts(qty, unitPrice, discountPct, taxRate, taxMode)`：

- **内部存储精度：** `DECIMAL(18, 4)`；每行对外账务过账汇总精度：**2 位小数四舍五入（Half Up / Standard Commercial Rounding 至 `0.01 AUD`）**。
- **逐行计算公式（AU 10% GST，`rate = 0.10`）：**
  1. `line_raw = round2(qty * unit_price * (1 - discount_pct / 100))`
  2. **`tax_mode = 'EXCLUSIVE'`：**
     - `net_amount = line_raw`
     - `tax_amount = round2(net_amount * tax_rate)`
     - `gross_amount = net_amount + tax_amount`
  3. **`tax_mode = 'INCLUSIVE'`（MVP 场景 1 & 3 核心路径）：**
     - `gross_amount = line_raw`
     - `tax_amount = round2(gross_amount * tax_rate / (1 + tax_rate))` *(10% GST 即 `round2(gross_amount / 11)`；如 `110.00 -> tax = 10.00, net = 100.00`)*
     - `net_amount = gross_amount - tax_amount`
  4. **`tax_mode = 'NO_TAX'`：**
     - 强制 `tax_rate_code = 'BASEXCLUDED'`，`tax_amount = 0.00`，`net_amount = gross_amount = line_raw`。
- **单据级汇总：** `sub_total = SUM(line.net_amount)`，`total_tax = SUM(line.tax_amount)`，`total = SUM(line.gross_amount)`（恒等式 `sub_total + total_tax == total` 必成立）。
- **科目适用性校验：** 提交过账前核验每行所选 `tax_rate` 对 `account.account_class`（`REVENUE/EXPENSE/ASSET/LIABILITY/EQUITY`）的 `can_apply_to_*` 标志必须为 `true`（`E06-NET`）。

## 3. 各核心业务过账规则矩阵（Posting Matrix）

| 业务事件 | 触发条件 | 借方 (Debit) | 贷方 (Credit) | `source_type` | `tax_type` 落点 |
|---|---|---|---|---|---|
| **销售发票批准 (`Invoice Approve`)** | `DRAFT/SUBMITTED -> AUTHORISED` | `610 AR`: `total` | `line.account` (`200`): `line.net`<br>`820 GST`: `SUM(line.tax)` | `ACCREC` | 收入行带 `OUTPUT` / `EXEMPTOUTPUT` 等 |
| **销售发票作废 (`Invoice Void`)** | `AUTHORISED` 且 `amount_paid == 0 && credits == 0` | 逆向冲销原分录 | 逆向冲销原分录 | `ACCREC_REVERSAL` | 税行同向取反，冲减 BAS |
| **客户贷项单 (`Sales Credit Note`)** | 批准退货折让（与 Invoice 共享序列号） | `line.account`: `line.net`<br>`820 GST`: `SUM(line.tax)` | `610 AR`: `total` | `ACCRECCREDIT` | 批准即逆向冲减 `1A` 与 `G1`；`Allocate` 至发票时在 `610 AR` 记互抵行并在 Cash BAS 生成 `CN(-)/INV(+)` 净零对冲行 (`E33`, `E35`, `E36`) |
| **客户收款核销 (`Receive Payment`)** | 匹配 Invoice（或直接收款） | `Bank`: `paid_amount` | `610 AR`: `paid_amount` | `ACCREC_PAYMENT` | **0 新增税额（Accrual 不计 BAS；Cash BAS 按收款比率触发发票行税码）** |
| **采购账单批准 (`Bill Approve`)** | `DRAFT/SUBMITTED -> AUTHORISED` | `line.account` (`400+`): `line.net`<br>`820 GST`: `SUM(line.tax)` | `800 AP`: `total` | `ACCPAY` | 费用/资产行带 `INPUT` / `EXEMPTEXPENSES` 等 |
| **供应商付款核销 (`Pay Bill`)** | 匹配 Bill | `800 AP`: `paid_amount` | `Bank`: `paid_amount` | `ACCPAY_PAYMENT` | 同收款原则 |
| **银行直接收款 (`Bank Receive / Cash Coding`)** | `BankRec Create` / `Cash Coding` | `Bank`: `total` | `line.account` (`200`): `line.net`<br>`820 GST`: `SUM(line.tax)` | `CASHREC` | 收入行直接带 `OUTPUT` 进 `1A` & `G1` |
| **银行直接付款 (`Bank Spend`)** | `BankRec Create` / `Cash Coding` | `line.account`: `line.net`<br>`820 GST`: `SUM(line.tax)` | `Bank`: `total` | `CASHPAID` | 支出行直接带 `INPUT` 进 `1B` & `G11` |
| **银行互转 (`Bank Transfer`)** | Bank A -> Bank B | `Bank B`: `amount` | `Bank A`: `amount` | `TRANSFER` | `BASEXCLUDED`（不计入损益与 BAS） |
| **手工日记账 (`Manual Journal`)** | `Post`（含可选 `auto_reverse_date`） | 各借方行 net（及含税拆分进项税至 `820`） | 各贷方行 net（及含税拆分销项税至 `820`） | `MANJOURNAL` | 若选 `Exclusive/Inclusive`，按行税码记税 |

## 4. 期间锁账、虚拟年结与 BAS 税务引擎

### 4.1 两层锁账日期校验（Two-Tier Lock Dates Validation）
在所有改变总账的命令入口统一执行 `assertPeriodOpen(org, effectiveDate, actorRole)`：
1. 若 `effectiveDate <= org.hard_lock_date`：**无条件拒绝（HTTP 422 `PERIOD_HARD_LOCKED`）**，即使 `Adviser` 也必须先显式解锁。
2. 若 `effectiveDate <= org.soft_lock_date` 且 `actorRole != 'ADVISER'`：**拒绝（HTTP 422 `PERIOD_SOFT_LOCKED`）**；`Adviser` 角色与已配置银行规则自动对账（可选配置）放行。

### 4.2 虚拟财年结转与报表计算（Virtual Year-End Close）
- 定义财年计算函数 `currentFyStart(org, asOfDate)`：若 AU 财年末为 `30 June`，则：
  - `asOfDate.month >= 7` -> `asOfDate.year-07-01`
  - `asOfDate.month <= 6` -> `(asOfDate.year - 1)-07-01`
- **Trial Balance (`asOfDate`)：**
  - 资产/负债/权益（含已录入的期初余额）汇总所有 `journal_date <= asOfDate`；
  - 损益科目（`REVENUE`, `DIRECTCOSTS`, `EXPENSE`）仅汇总 `currentFyStart <= journal_date <= asOfDate`；
  - 所有 `< currentFyStart` 的历史上期损益净额自动聚合累加至 `960 Retained Earnings`！
- **Balance Sheet (`asOfDate`)：**
  - `Current Year Earnings` = `[currentFyStart, asOfDate]` 的净盈利（Revenue - Costs - Expense）；
  - `Retained Earnings` = `960` 科目前期期初余额 + `< currentFyStart` 历史累计损益；
  - 若某 `BANK` 科目净额 `< 0`（透支），在报表序列化阶段动态移入 `Liabilities -> Current Liabilities` 节点展示（不改总账科目分类）。

### 4.3 AU Simpler BAS 引擎与 `G1` 口径策略
1. **BasField 映射驱动：** 每条带税码的 `journal_line` 通过 `tax_rates.bas_field_names` 声明归属（如 `OUTPUT -> ["1A", "G1"]`, `INPUT -> ["1B", "G11"]`, `EXEMPTOUTPUT -> ["G1", "G3"]`）。
2. **`Accruals` vs `Cash` 归属过滤：**
   - **Accruals：** 直接提取区间内过账日期在 `[start_date, end_date]` 的源交易明细行（`ACCREC`, `ACCRECCREDIT`, `ACCPAY`, `ACCPAYCREDIT`, `CASHREC`, `CASHPAID`, `MANJOURNAL`）；**排除 `ACCREC_PAYMENT` / `ACCPAY_PAYMENT`**。
   - **Cash：** 对 `CASHREC / CASHPAID / MANJOURNAL(show_on_cash_basis=true)` 直接按交易日归入（实测 `E35`/`E36` 验证 Cash P&L 与 Cash BAS 对手工凭证和未付款 Bill 处理完全同构）；对发票/账单，仅当 `Payment` 发生日落在 `[start_date, end_date]` 内时，按比例 `proportion = payment_amount / invoice_total` 折算原发票各明细行的 Gross / GST / Net 计入当期报表与 BAS（Credit Note Allocation 则生成与所核销发票相抵的正负对称行）。
3. **`G1 Total sales` 含税/不含税显式配置（关键兼容设计）：**
   - 组织设置表增加 `bas_g1_mode ENUM('INCLUSIVE', 'EXCLUSIVE')`：
     - **默认值 `'INCLUSIVE'`（对齐 Xero AU 实测 `E28-PAGE` `G1 = 220`）**：`G1` 累加 `total_gross`。
     - **可选值 `'EXCLUSIVE'`（对齐 `调研需求` MVP 用例中 `G1 = 200` 及部分会计师习惯）**：`G1` 累加 `total_net`。
   - UI 页面明确标注当前模式徽章（`"GST inclusive"` vs `"GST exclusive"`），保证两端口径透明可验！
4. **水位线（Watermark）防漏报：**
   - 每次 `Finalise BAS` 持久化 `min_journal_number`、`max_journal_number`、`status = FINALISED`。
   - 查询下一期草稿时，同时检索日期在本期内的新分录，以及 **`journal_date < current_period_start AND journal_number > last_finalised_max_journal_number`** 的迟到补录凭证，在 `Unfiled amounts` 区显式汇总并计入当期净应缴/应退（`Payment 9 = 1A - 1B + adjustments`）。
