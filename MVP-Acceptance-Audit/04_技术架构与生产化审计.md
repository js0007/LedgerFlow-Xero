## 二、重点技术重构与生产化建议

### 2.1 安全与多租户隔离（不可妥协的上线前红线）
1. **真实认证中间件：** 在所有 `/api/v1/*` 业务路由前置 JWT / HttpOnly Session 验证，解析可信 `user_id`；`get_actor` 严格查验 `(user_id, org_id)` 在 `org_memberships` 中的真实权限记录。
2. **废弃任意切角色接口：** 生产环境彻底下线 `/auth/switch-role`（仅保留在 `FLASK_ENV=development && DEMO_MODE=1` 沙盒），真实权限调整须由 `SUBSCRIBER`/`ADMIN` 通过 `POST /orgs/<org_id>/memberships` 变更他人权限并记入审计日志。
3. **全局跨组织外键防守：** 在 Service 层统一建立 `assert_owned(conn, table, row_id, org_id)` 辅助函数；或在所有业务表（如 `quotes`, `invoice_lines`, `payments`）逐步引入复合外键 `(org_id, contact_id)`，从数据库引擎层杜绝跨组织引用泄漏 **[已验证需修]**。

### 2.2 事务模型、并发控制与 PostgreSQL 迁出策略
1. **消除 TOCTOU 先读后锁：** 将 `record_payment`、`approve_invoice`、`allocate_credit_note`、`reconcile_statement_line` 中**所有前置读取（发票欠款、版本、锁账检查）全部移入 `with atomic_tx(conn):` 内部**；在未来迁移 PostgreSQL 时对目标单据行追加 `FOR UPDATE`。
2. **幂等记录同事务落盘：** 让 `save_idempotency` 在业务逻辑提交前的同一个事务内执行 `INSERT INTO idempotency_records`，保证“业务入账”与“幂等存根”严格同生共死（Atomicity）。
3. **SQLite → PostgreSQL 平滑路线：** 当前保持 `services/` 纯业务逻辑接口不变，引入 `SQLAlchemy Core` 或轻量 Repository 方言适配层 + **Alembic**，把当前 `accounting_core_sqlite.sql` 迁移为可版本化的 DDL 迁移脚本，将不可变触发器转为 PG `BEFORE UPDATE OR DELETE` PL/pgSQL 触发器函数与 Row-Level Security (`CREATE POLICY org_isolation`) **[代码推断]**。

### 2.3 契约校验与前端结构拆分
1. **后端请求校验：** 引入 Pydantic v2 Schema 对所有 `POST`/`PATCH`/`PUT` 请求体做前置结构校验，捕获 `ValidationError` 并统一格式化为 HTTP `400/422` 错误 JSON，杜绝裸 `KeyError` 触发 HTTP 500 **[已验证需修]**。
2. **前端架构清理：** 引入 `react-router-dom` 替换内存路由；按领域拆分为 `hooks/useInvoices.ts`、`components/bank/MatchTab.tsx`、`components/bank/CashCodingGrid.tsx`、`components/reports/BasView.tsx` 等小粒度模块（单文件控制 < 350 行）。
